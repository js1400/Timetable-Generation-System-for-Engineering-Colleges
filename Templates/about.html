Algorithm Details

How Backtracking + Graph Coloring solve the timetable problem

🔁 Backtracking Algorithm

What is it?

A depth-first search technique that incrementally builds solutions and abandons ("backtracks") a candidate as soon as it violates a constraint.

How it works here

Each subject needs N hours per week. The algorithm tries every (day, period, room) combination. If a slot is conflict-free, it assigns it; otherwise it tries the next slot.

  • Pick next unassigned subject-session (MRV heuristic)
  • Try all (day, period, room) slots in random order
  • Check constraints: teacher free? room free? no graph conflict?
  • Assign if valid; recurse to next subject
  • If no slot works → backtrack and try different slot for previous subject
  • Repeat until all subjects are scheduled
🎨 Graph Coloring Model

Graph Construction

Each subject is a node. An edge is added between two subjects if they share the same teacher (they cannot be scheduled at the same time).

Coloring = Time Slots

Each "color" represents a (day, period) timeslot. The constraint: no two adjacent nodes (conflicting subjects) can have the same color (same timeslot).

  • Build conflict graph from teacher assignments
  • Sort subjects by degree (most conflicts first)
  • Assign smallest available color (timeslot) to each node
  • Ensure no adjacent nodes share a color
  • Backtracking handles cases where greedy coloring fails
  • Result: provably clash-free schedule
📏 Constraints Enforced

Hard Constraints

• A teacher cannot take two classes at the same time
• A room cannot host two classes simultaneously
• No class can appear twice on the same day

Soft Constraints

• Subjects spread across different days
• MRV heuristic minimizes backtracking
• Random slot shuffling for variety

Complexity

• Time: O(slots^subjects) worst case
• Pruning reduces practical runtime
• MRV keeps it fast for typical college inputs
